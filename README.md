# دارا (Dara)

داشبورد فارسی مدیریت پرتفوی و گردش حساب، با گزارش تطبیق سرمایه و امکان بررسی و ویرایش ردیف‌های نیازمند اصلاح. داده‌های پرتفوی در `localStorage` همان مرورگر ذخیره می‌شوند؛ این حافظه **رمزگذاری‌شده نیست** و جای نسخهٔ پشتیبان را نمی‌گیرد.

## دانلود نسخه

1. صفحهٔ [Releases دارا](https://github.com/mjavidnazar/Dara/releases) را باز کنید و نسخهٔ موردنظر را انتخاب کنید.
2. در قسمت **Assets**، روی **Source code (zip)** بزنید و فایل را از حالت فشرده خارج کنید.
3. این ZIP **کد منبع** است، نه برنامهٔ نصب‌شدنی یا فایل اجرایی مستقل. داده‌ها و نسخه‌های پشتیبان شخصی شما داخل آن نیستند.

## اجرا روی رایانه

به [Node.js](https://nodejs.org/) نسخهٔ **22.13 یا جدیدتر** و npm نیاز دارید. در ترمینال، داخل پوشهٔ استخراج‌شده اجرا کنید:

```bash
npm ci
npm run dev
```

سپس `http://localhost:3000` را در مرورگر همان رایانه باز کنید. برای متوقف‌کردن برنامه در ترمینال `Ctrl+C` را بزنید. با `npm run build` می‌توانید ساخت نسخهٔ تولیدی را بررسی کنید. این پروژه یک برنامهٔ Next.js است؛ برای اجرای تولیدی از خروجی `standalone` همراه فایل‌های `public/` و `.next/static/` استفاده کنید.

> اگر فایل JSON پشتیبان خود را دارید، آن را **فقط در خود برنامه** از بخش «پشتیبان‌گیری» و پس از تهیهٔ نسخه از داده‌های فعلی بازیابی کنید. فایل پشتیبان شخصی، `.env` یا اطلاعات مالی را در مخزن عمومی GitHub بارگذاری نکنید. برچسب‌های خطا فقط برای بررسی‌اند و داده‌ای را خودکار اصلاح نمی‌کنند.

## جابه‌جایی معاملات هم‌روز

در بخش «معاملات»، جدول را بر اساس «تاریخ معامله» مرتب کنید. دستگیرهٔ کنار ردیف را با ماوس یا لمس بکشید، یا از دکمه‌های بالا/پایین (و کلیدهای جهت‌نما هنگام تمرکز روی دستگیره) استفاده کنید. جابه‌جایی فقط میان ردیف‌های **همان روز** انجام می‌شود؛ هنگام فعال بودن فیلتر، حرکت نسبت به ردیف‌های نمایان است.

ترتیب انتخاب‌شده در همین مرورگر و در خروجی پشتیبان JSON ذخیره می‌شود. این تنظیم فقط **ترتیب نمایش** را عوض می‌کند؛ تاریخ، ساعت، مبلغ، تسویه و محاسبات مالی را تغییر نمی‌دهد و برای معاملات فاقد ساعت، ساعت ساختگی نمی‌سازد. ردیف‌هایی با شناسهٔ تکراری تا رفع ابهام قابل جابه‌جایی نیستند.

## اولویت قیمت‌های هم‌روز

برای ارزش‌گذاری دارایی و سهام، ابتدا **جدیدترین تاریخ معتبر** انتخاب می‌شود؛ اگر برای آن روز چند قیمت ثبت شده باشد، **آخرین قیمتی که ثبت یا ویرایش کرده‌اید** مبنای محاسبات و نمودار است. ثبت قیمت تازه، قیمت‌های قبلی را حذف نمی‌کند؛ ویرایش یک رکورد نیز به رکوردهای دیگر دست نمی‌زند. ترتیب ثبت/ویرایش در پشتیبان JSON و پس از بارگذاری دوباره حفظ می‌شود. برای پشتیبان‌های قدیمی که زمان ثبت قیمت ندارند، آخرین رکورد موجود در آرایهٔ همان روز به‌طور قطعی انتخاب می‌شود. قیمت نامعتبر یا مربوط به آینده همچنان در گزارش برای اصلاح نمایش داده می‌شود و در ارزش‌گذاری به کار نمی‌رود.

## هفت شاخص در «گزارش‌ها»

خلاصهٔ بالای گزارش، مستقل از باز بودن بخش جزئیات، کل سرمایهٔ اولیه و آورده‌های بعدی، سود محقق‌شده، جمع سود محقق‌شده و جاری، ارزش روز دارایی‌های فعلی، بهای خرید موجودی فعلی و دو نسبت را نشان می‌دهد: **سود محقق‌شده ÷ (سرمایهٔ اولیه + آورده‌های بعدی)** و **(ارزش روز دارایی‌ها + سود محقق‌شده) ÷ سرمایهٔ اولیه**. برداشت‌ها جداگانه نمایش داده می‌شوند و از مخرج هیچ‌کدام کم نمی‌شوند. در نسبت دوم، آورده‌های بعدی هم به مخرج اضافه نمی‌شوند. اگر مخرج مربوط به هر نسبت معلوم و مثبت نباشد، درصدی حدس زده نمی‌شود. چون ماندهٔ نقدی در ارزش روز وجود دارد، افزودن سود محقق‌شدهٔ باقی‌مانده در نقد ممکن است به دوباره‌شماری منجر شود؛ نسبت دوم شاخص بازدهی خالص یا ارزش واقعی سبد نیست.

سود محقق‌شده شامل سود/زیان فروش دارایی و سهام، سود مجمع **پرداخت‌شده** و سود واریزی حساب‌های نقدی (با کسر هزینه‌های ثبت‌شده) است؛ سود مجمع پرداخت‌نشده جزو سود محقق‌شده نیست. بهای خرید موجودی فعلی فقط موقعیت‌های باز را با بهای تمام‌شده‌شان و ماندهٔ حساب‌های نقدی را با ارزش اسمیِ امضادار در نظر می‌گیرد. اعداد از داده‌های ثبت‌شده محاسبه می‌شوند، نه از حدس دربارهٔ منشأ سرمایه؛ تا زمان رفع هشدارهای تطبیق، مقادیر و نسبت‌های نمایش‌داده‌شده «خام و نیازمند بررسی» هستند. حتی نبودِ هشدار داخلی جای تطبیق با صورت‌حساب‌ها را نمی‌گیرد.

## توسعه و کنترل

```bash
npm test
npm run lint
npm run build
```

نسخهٔ منتشرشده را از صفحهٔ Releases بگیرید؛ گزینهٔ **Code → Download ZIP** در صفحهٔ اصلی مخزن ممکن است مربوط به شاخهٔ `main` و نسخه‌ای متفاوت باشد.
